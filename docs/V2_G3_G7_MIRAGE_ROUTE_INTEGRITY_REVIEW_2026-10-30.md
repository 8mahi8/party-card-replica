# V2 G3/G7｜〈蜃気楼〉多人数対象ルーターの整合性レビュー

更新: 2026-10-30（日本時間）／開発Draftのみ

## 今回の目的

3〜9人〈蜃気楼〉研究用ルールセットの対象移動を、原作未確認の挙動を追加せずに堅牢化する。先に実装済みの「攻撃対象を1人ずつ処理する」研究ルートは残す。**この変更は原作ルールを追加・確定するものではない。**

## 原作の根拠と未確認点

- [ゴッドフィールドwiki・奇跡一覧](https://w.atwiki.jp/piong/pages/20.html)：〈蜃気楼〉の新仕様では対象ごとの逐次解決、未攻撃の生存者を選ぶ旨を説明。
- [GFガイド＋α・奇跡一覧](https://w.atwiki.jp/gfplusa/pages/19.html)：複数の〈蜃気楼〉は人数に応じて複数周回、〈壁〉は無属性の武器攻撃を止める旨の記述。
- [まかろんのゲームメモ・神器一覧](https://macarongamemo.com/entry/godfield-artifact)：現行に近い参考のカード説明、〈蜃気楼〉MP5と全体攻撃化。

**未確認**：1発目の対象を手動指定するのか、全員からランダムか。〈壁〉・反射・弾きが多段攻撃全体を打ち切るか各発だけ止めるか。これらは本家クライアントを直接観測するまで原作再現ルールに昇格しない。研究ルールセット `mirage-multiplayer-research-fixture-v2` の明示的仮定を継続。

## 改善したルーターの不変条件

対象ルーター `v2/mirage-target-route.mjs` に限定し、既存の決定的な乱数列、攻撃力、属性、MP、補充やUIは変更しない。

1. `route.visitedIds` の最後の要素は必ず現在の `targetId`。攻撃済み履歴に未防御の未来のプレイヤーを紛れ込ませた状態を受け付けない。
2. 記録される訪問の個数は「解決済みの命中数+最初の対象」の範囲を超えられない。初回時点に他の相手を「訪問済み」として捏造できない。
3. `advanceMirageTargetRouteFixture` は途中の乱数抽選が不要な経路（攻撃元死亡・全対象脱落・最終周終了）でも `rngSeed` の範囲と整数性を検証。後続の通信・保存で無効seedを許容しない。
4. 誤ったデータは常に例外で拒否し、入力 `route` / `players` を書き換えない。

これは防御の権限検証そのものの代替ではない。オンライン化時には既存の `authorizedSeatId`、`expectedRevision`、command ID の再送防止に加え、信頼できるホスト側の原子的CAS永続化が必要。

## テスト

`tests/mirage-target-route-v2.test.mjs` に以下の Node 回帰2ケースを追加。

- 現在の対象以外で終わる偽の `visitedIds`、未実行命中を前提にした偽の訪問件数を拒否。正常ルートでは次の対象へ進行する。
- 2人戦で最後の相手が脱落済みでも、`undefined`、ゼロ、負数、NaN、文字列、32-bit範囲超過のseedを拒否。有効seedでは正常に終了する。

CI成功が確認できるまでテスト成功と報告しない。ブラウザ自動テスト、原作実機・学校iPadを混同しない。

## 次の仕事

〈蜃気楼〉の初回対象と、〈壁〉・反射・弾きの正規処理を原作プレイ記録等で確定させる。3席ホットシートの自動操作は済んでいるが、実機iPadのタッチ・画面確認およびオンラインG6は未完成。特にオンライン化前には「クライアントが攻撃済み履歴や乱数を指定できない」境界を維持する。
