# V2 G5｜実ブラウザ・画面表示の検証（2026-10-27）

## 実施内容

V2の開発用オフライン・ホットシートUIを、**実際のChrome / Chromium**で操作するテストを導入。ブラウザを起動し、キーボードのないタッチ環境に近い条件で画面操作とレイアウトを検証する。

- **追加ファイル** `tests/v2-browser-smoke.browser.mjs`
  - Node.js 22 の標準 `WebSocket` とChrome DevTools Protocolを使用。PlaywrightやSeleniumの外部ライブラリ不要。
  - 実ブラウザを`file://`の単体HTMLで起動し、カードのボタンを座標からクリック、画面が更新されることを確認。
  - iPad横向き相当の1024×768、狭い画面の390×844を測定。
  - テスト結果とスクリーンショットはGitHub Actionsアーティファクトとして保存。
- **CI追加** `.github/workflows/v2-browser-smoke.yml`
  - PRでV2などが変わった時だけ起動。通常の `npm test` とは独立させ、Node系のテストがブラウザ未導入環境で失敗しないようにした。
  - GitHubホストのChromeを使用し、日本語のNoto CJKフォントもインストールして画像を確認できる状態にする。

## 初回ブラウザ結果

GitHub Actions実行 **40516126080**：
- **13チェック成功**：初期手札の非表示、iPad幅の横はみ出しなし、カード表示、カード選択のハイライト、44px以上のカード高さ、攻撃確定→相手の手札隠し、防御選択、次のターン・初期化、モバイル幅の表示とタップ領域。
- 既存のルールテスト **301/301件成功**（run 40516126276）。
- スクリーンショットは `v2-browser-evidence` アーティファクトに記録した。

## スクリーンショットで気づいた点と修正

1. GitHubホストのChromeでは最初、日本語部分が四角い代替文字として表示された。これは日本語フォントが入っていない**CI環境の問題**で、実際のiPadの日本語表示不良だと決まったわけではない。CIへNoto CJKのインストールを追加した。
2. 画面のプレイヤー表示が「PA」「PB」になっていたため、**P1 / P2**に変更した。内部で使う席IDは引き続きA・Bで、エンジンや通信設計には影響しない。
3. 手札や習得済み奇跡が縦に長いと、確定ボタンまでスクロールが必要。画面下に**常時見える確定バー**を追加し、カード一覧の下にはボタンに隠されない余白を確保。
4. ブラウザ試験に「モバイル表示中でも確定ボタンが可視領域に入り、44px以上の高さがある」を追加。

## 確認できること／確認できないこと

確認できること：
- Chromeの実際の画面・クリック・レイアウトの一連の基本操作
- ブラウザコードのロード成功（実際の単体HTMLファイルを使用）
- 画面横幅・ボタンの寸法・秘密手札の切り替え
- 変更後もNode.jsの既存テストが通るか

**確認できないこと**：
- SafariとChromeの挙動が同じか、実際の学校iPad Safariで問題ないか
- Google Sitesのコード埋め込み枠（iframe）におけるスクロール、画面高さ、タップや再起動
- 2台のiPad間の通信（オンライン処理自体が未実装）
- 原作の画面・全カード・内部処理・抽選確率の再現

## 再実行方法

GitHub Actionsの **V2 real-browser smoke (development only)** を確認。ローカルでChromeが入っていれば：

```bash
node v2/demo/build.mjs --check
node tests/v2-browser-smoke.browser.mjs
```
