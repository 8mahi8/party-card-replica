# G3｜虹のカーテンと属性防御：武器・奇跡の共通計算へ統合

2026-10-28 / 開発ブランチ `refactor/v2-foundation-review-20261027` / Draft PR #1

## 原作照合の根拠

- [ゴッドフィールドwiki：防具・防御用雑貨](https://w.atwiki.jp/piong/pages/17.html)
  - 虹のカーテンは攻撃の属性を取り除く（研究用参照データ：価格15、参考枠3）。
  - 防具は有効属性のものを好きな数選んで守備力を足す。
- [アニヲタWiki ゴッドフィールド解説](https://w.atwiki.jp/aniwotawiki/pages/47010.html)
  - 虹のカーテンで光属性も無属性扱いとなり、通常防具による防御が可能。
  - 闇属性も無属性化され、ダメージが残っても即死を防止できる。
- [HIMATAMI](https://himatami.jp/games/33)・[ゴッドフィールドwiki：ゲームの仕様](https://w.atwiki.jp/piong/pages/16.html)
  - 属性の防御相性、闇属性の1以上の被弾で即死、光属性には通常防具が無効。

これらは第三者情報であり、ゲーム本体の実通信を直接観測した結果ではない。ルールの新規仮定は追加しない。

## 実装

### 共通の属性・防具演算
- もともと`src/rules.mjs`に存在した`sumLegalArmor()`を再利用し、武器経路`v2/basic-resolution.mjs`と奇跡経路`v2/miracle-resolution.mjs`の重複した`canBlock`判定・防具加算を統一。
- 虹のカーテン（`stripElement`）は各経路で「最初に選ぶ」ことを検査したあと、共通演算へ`rainbowCurtain:true`を渡す。
- **奇跡を止めるエンゼル防具**は数値ガードと別の`stopped`効果を持つ。従来どおり属性相性によらず奇跡を止める特例を維持。反射・弾くは従来の専用解決経路が担当。
- 共通演算に**安全整数の上限**を追加。異常に大きな防具値を誤った浮動小数点の値で続行しない。現行カードの通常動作を変えない。
- 共有後も既存UIやテストが予期するエラーメッセージを残した（「Illegal shield」と「incompatible shield」の双方を含む）。
- 単体HTMLは旧`demo/standalone.html`とV2`v2/demo/standalone.html`の両方をビルド元ソースに同期済み。

### 原作に沿う回帰テスト

`tests/rainbow-defense-parity-v2.test.mjs`（9件）:
1. 光武器・光奇跡への通常防具はカーテン無しでは拒否、処理は原子的。
2. 光武器＋虹→通常防具でHP40を維持。
3. 光奇跡`m006`（流星 攻10）＋虹→守5でHP35、MP7を支払う。
4. 闇武器`w025`の無防御は即死、虹のみならHP39で生存。
5. 闇奇跡`m003`の無防御は即死、虹のみならHP35で生存。
6. 闇奇跡＋虹→革の帽子でHP36。
7. 防具→虹という逆順は両経路で拒否、元状態不変。
8. 共通演算の属性マトリックスと虹の上書きを確認。
9. 過大なガード合計・危険な整数を拒否。

`tests/v2-webkit-smoke.browser.mjs`に実際の画面タップ2シナリオを追加:
- 流星（光）→虹のカーテン→アイアンアーマーでHP35、攻撃者MP3、次手番。
- 闇→虹のカーテンでHP35となり即死しない、攻撃者MP5、次手番。
