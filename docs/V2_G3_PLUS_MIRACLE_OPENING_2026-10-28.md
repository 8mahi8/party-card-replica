# V2 G3｜火の玉・流星を先頭に選ぶ場合の攻撃分類（2026-10-28）

## 調査した資料と証拠

**最重要の技術証拠**：[oreapo「God Field超分析 #7 Bot作成編2（フレーム）」2025-10-05](https://note.com/oreapo_note/n/n7791e8e30943)
- 原作ゲームのAPIを使ったBOTの行動候補生成・サーバーの組合せ判定を検証した筆者による詳細記録。
- 火の玉／流星のような「＋攻」の**奇跡を最初に選んだ場合は独立した奇跡攻撃**であり、「流星＋力の粉」「流星＋火の玉」のような複合は**サーバーから拒否**されると明記。
- 〈パンチ＋火の玉＋火の玉＋精霊のぬいぐるみ〉では、精霊が直前の火の玉のMPだけを無料にし、合計消費MPは2。順番に意味がある。
- 著者は本家API経由で検証したと説明しているが、**今回AIが本家サーバーに接続して再現操作した証拠ではない**。特に〈奇跡先頭＋追加武器〉の個別ペア全件の直接拒否を示すものではない。奇跡先頭の独立分類と、実際に列挙された拒否例から導いた研究用制限として扱う。

**補助資料**：
- [ゴッドフィールドwiki 神器一覧](https://w.atwiki.jp/piong/pages/15.html) に通常武器・追加武器の区別。
- [初心者向けゴッドフィールドルール](https://godfield-beginner.game-info.wiki/) に「攻」と「＋攻」の差。
- [2021年の実プレイヤー攻略記事](https://ameblo.jp/shibransk/entry-12647363984.html) に、火の玉／流星の単体奇跡・武器に加える使い方、光属性の通常混合に関する解説。ただし現在版と変更があり得る。
- [God Fieldガイド＋α 奇跡](https://w.atwiki.jp/gfplusa/pages/19.html) に火の玉は火+2 MP2、流星は光+10 MP7。

## 今回の実装で維持・修正した範囲

1. `v2/staging-room.mjs`: `playSequence`（手札と習得済み奇跡を並べて選ぶコマンド）でも、**最初が手札由来の攻撃奇跡**であれば選択できるよう修正。`playCards`で既に許可されていた挙動と統一。手札からの奇跡後に精霊を選ぶ合法な並びを使える。
2. `v2/miracle-resolution.mjs`: `attackSequence`と`attackInstanceIds`の一致を必須にし、〈火の玉〉先頭の後ろに習得済み奇跡を混ぜると、**無視して奇跡1枚で処理するという不正な成功を禁止**。リクエスト全体を失敗させ、Roomの状態は書き換えない。
3. `v2/lab-controller.mjs`: 火の玉と流星をカードに印字されている**「＋攻2」「＋攻10」**として表示。攻撃奇跡単体でも起こせる仕様を消さない。
4. `v2/lab-ui.mjs`: 火の玉／流星を最初に選ぶと**単独奇跡として処理され、精霊のみ直後に選べる**ことを選択欄の横に表示。武器先頭のときは元の簡潔なヒントを保持。
5. **戦闘本体で既に成立していた挙動は無理に変更しない**：火の玉単独＝火攻2 MP2、流星単独＝光攻10 MP7、武器先頭→火の玉は武器攻撃に攻2加算。後者では防御側の「奇跡を止める」ではなく武器向けの防御が対象。
6. 一方〈武器→火の玉→追加武器〉の正確な合法性（新たな追加武器の選択順）は、一次の操作画面で確認できず**今回も未確認のまま**。`v2/ordered-attack.mjs`が明示的に拒否する現行の研究用制限はそのままにした。本家で禁止されると断定したわけではない。
