  - **弾く**：自分を含む全生存預言者のいずれかに攻撃を返す。
  - **自分に弾き返された場合**：再度「止める・弾く・跳ね返す」を選べない。

## 実装した共通処理

新規 `v2/redirect-route.mjs` の `planRedirectRoute(state,{mode,sourceId,targetId,deflectRng})`：

- `reflect` → 以前の攻撃者へ返す。RNGは消費しない。
- `deflect` → HP>0の席だけをゲームの席順で並べ、**現防御者自身も含めて**1件を選ぶ。固定シードの開発用生成器は**1回だけ**進む。
- `deflectRng` 注入ではテスト側だけが決定論的な値を供給。ゲーム状態のシードは変更しない。
- 弾き先が防御者自身なら `immediate:true`、**再度の防御機会は渡さず即時ダメージ判定**。それ以外の転送ではターン継続。
- 戻り値は `{route,nextSeed,immediate}` の不変な計画。手札消費・MP支払い・補充・ターン進行・対戦状態の変更は行わない。
- 送信元・受信者の両方が生存中であること、mode、RNG範囲などを検証。エラーでは元状態不変。

元の二重実装からの移行先：

- `v2/redirect-resolution.mjs`（物理武器への跳ね返す／弾く）
- `v2/miracle-resolution.mjs`（単独奇跡への月光／スカイ系、スーパーミラー、乱気流など）
- 両エンジンともコスト・属性・防御・奇跡習得の専用コンパイラは維持し、**移動先と乱数に関する共通ルールだけ**抽出した。奇跡と武器を同じ攻撃種別として扱う修正はしていない。
- `v2/demo/build.mjs` に新規moduleを依存順に挿入、`v2/demo/standalone.html` を再生成。WebKitの開発fixture参照番号も同期。
- `main`とGoogle Sites公開版には一切変更なし。

## 制限と今後の方針

- 新規機能は**共通ルート計算**のみ。反射後の特殊な吸収、全体攻撃、指輪カウンター、相手の蘇生などは未実装・未検証。
- このゲームはまだV2の**90種類・209参照枠**の部分台帳。原作の抽選を実装したわけではない。固定`d001`補充のローカル研究環境である。
- **原作APIを直接操作したわけではない**ので、正確な原作との合致を保証するものではない。
- 「ちからの粉→オーラ」のダメージ数値は未確認。推測実装しない。
- G3では今回のルート計算に引き続き、反射・防御方法の**切り替えUI**、コスト・補充・攻撃の元属性を別効果クラスとして検証し、G4原作goldenケースに進む。オンラインG6と全カードG7は未完。
