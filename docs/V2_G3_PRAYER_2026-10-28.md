# V2 G3｜「祈る」の忠実再現と上限18枚の補充（2026-10-28）

## 原作の根拠（実装より先に調査）

- [ゴッドフィールドwiki／ゲームの仕様](https://w.atwiki.jp/piong/pages/16.html)：祈るのは**武器がない時だけ**、神器を**1枚**引く。18枚で祈るとランダムな神器が捨てられると記述。
- [初心者向け操作ガイド](https://godfield-beginner.game-info.wiki/)：「武器の神器をひとつも所持していない場合のみ、何も選択せずに決定」で祈り、「ターンをスキップ」と明記。
- [2026-09-30のプレイヤーQ&A](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q14331754699)：武器が手札にある場合は祈れず、18枚なら古い神器からランダムに捨てられるという説明。
- [God Field考察・手札を増やす](https://ameblo.jp/godfield-tactics/entry-12099641663.html)：祈るのは自分だけのカードを1枚増やす手段であり、武器なしの状態に限るという解説。

上記はいずれも**第三者資料**。AIが2026年の本家サーバーで実操作して得た一次観測ではない。現在の原作抽選確率／乱数アルゴリズムは検証していない。

## 実装

### V2共有状態とコマンド

- `v2/staging-room.mjs` に `type:'pray'` を追加。許可プロパティは `commandId/expectedRevision/actorId/type` のみ。
- **自身の手札に `family:'weapon'` が1枚もないときだけ**許可。追加武器（＋攻）も武器として扱う。手札の奇跡・防具は武器ではない。
- 認証済み席・revision・同一commandIdの重複排除は他のコマンドと同様。相手への防御窓は開かず、共通効果キューへ渡す。

### 共通効果・乱数・再接続

- `v2/room-transition.mjs` の `resolvePrayFixture` が共有 `runEffectQueueFixture` を用い、`grantDraw -> refill -> advance` を一度で処理する。
- 0〜17枚：1枚増やして次手番。18枚：ホスト側の `drawRandom32(rngSeed)` で**既存18枚から1枚を無作為に選び**、それを消費→固定の研究カードで補充して18枚のまま次手番に進む。
- **乱数に使ったseedの更新は部屋状態へ反映**。同じ入力状態で同じ交換位置となり、再送でも二重ドローしない。これは**V2研究版の決定的な乱数**で、本家の乱数が同じだと主張しない。
- 使用カードのID重複や上限18枚の違反を避け、原子的更新を行う。MP/HP/お金には触れない。

### オフライン試遊UI

- `v2/lab-controller.mjs` で手札に武器がない場合、空選択の確定が `pray` になる。
- `v2/lab-ui.mjs` でその場合の確定ボタンは「祈る（神器を1枚引く）」と表示。攻撃できる奇跡があれば通常どおり選択して攻撃可能。
- 武器を持った状態の空選択は従来どおりエラー。カードや秘密情報が相手の画面へ漏れない。
- `v2/demo/standalone.html` は改修後の14モジュールから再生成。学校Google Sitesの公開版とは独立。

## テスト

`tests/prayer-v2.test.mjs` 新設（12件）で以下を回帰：

- 0枚、1枚、防具のみ、攻撃奇跡のみで祈れる。MP/HP/お金は不変で手番が進む。
- 単体武器、追加武器、ワンド持ちでは祈れない。状態を破壊しない。
- 権限・revision・不正プロパティ・重複コマンドを検証。
- 17枚→18枚、18枚→乱数で旧1枚を除去し、新IDのカード1枚を追加。複数の固定seedで再現。
- 3人部屋の進行と他人の手札秘匿。
- 画面の祈るボタン、ホットシートでの手番引継ぎ、攻撃奇跡を選ぶ場合の優先。
