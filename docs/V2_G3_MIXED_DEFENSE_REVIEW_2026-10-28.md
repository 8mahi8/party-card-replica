# V2 G3｜特殊防具の複合選択・安全な対応範囲レビュー（2026-10-28）

## 資料を確認した結果

参照対象：原作ゴッドフィールドと操作上の再現。以下は公開二次資料に基づく。原作サーバーの同一局面での実機検証は未実施。

- https://w.atwiki.jp/piong/pages/16.html — 防御時には防具を好きな数選べる。守備力は攻-守。属性防御には相性がある。
- https://w.atwiki.jp/piong/pages/17.html — スカイ系：奇跡を弾く。月光系：奇跡をはね返す。エンゼル系：奇跡を止める。虹のカーテン：属性を取り除く。
- https://godfield-beginner.game-info.wiki/ — 同時に複数の防具を選択可能、弾く先には自分を含む。
- https://w.atwiki.jp/piong/pages/21.html — はね返し後には再反射があり得ることを確認する戦術解説。
- https://ameblo.jp/godfield-tactics/entry-12100951333.html — 災い「栄光」の例外として防具を一つしか選べないとの旧版解説（栄光自体は未実装）。

**分かったこと**：防具を一度に複数使うこと、その合計守備値、虹のカーテンによる属性除去、各特殊防具の単独効果。

**まだ分からないこと**：奇跡が飛んできたときに、スカイと月光／エンゼルとスカイなど相異なる複数の特殊効果を同時に選ぶと、どれが優先されるか。何枚を消費してどれが発動するか。防具が複数あること自体から、この例外処理の結果を推測してはいけない。

## 実装したバグ修正

`v2/miracle-resolution.mjs` の共通防御エントリで、通常防御にも一律「最大3枚」制約がかかっていたため、原作でできる通常防具4枚・5枚の選択が拒否されていた。

- その汎用制約を除去し、入力レイヤーの `defendSequence` 上限（36ステップ）と合わせた。
- **特殊な奇跡の弾き/反射はこれまでどおり単独使用（または防御奇跡→直後の精霊）だけ**を実装する。複合特殊反応の優先度は未確定。
- `defense.sequence` と `defense.instanceIds`／習得済み奇跡IDとの順序・内容の一致検査を追加し、解決前に拒否する。これにより不正な順序情報に対して手札消費や追加ドローを起こさない。
- 戦闘後の補充は中央の効果キューが一括で担当。防具枚数だけ補充し、MPは攻撃奇跡の費用を二重計上しない。

## できる組み合わせ（検証）

1. 奇跡「氷」に「フレイムブーツ」4枚（合計守12）。
2. 同じ奇跡に「フレイムブーツ」5枚（合計守15、`defendSequence`で順序保持）。
3. 「虹のカーテン」→無属性防具4枚で水奇跡の属性を除去して守を合算。
4. 無属性武器「ワンダーソード」に「スカイブーツ」+「月光のよろい」+「アイアンアーマー」。奇跡専用反応は発火せず守を合算。
5. 属性武器「ほむら巻き」に「虹のカーテン」→「スカイヘルム」→「月光のよろい」→「革の帽子」。属性除去の後に守を合算。
6. 不正な「防具→虹のカーテン」は**コマンド入力段階**で拒否（次プレイヤーへ進まず、状態不変）。
7. 「スカイ+月光」など奇跡向け特殊効果の同時選択は未確認としてアトミックに拒否。

`tests/mixed-special-defense-v2.test.mjs` 12件＋ `tests/lab-ui-v2.test.mjs` の実コントローラ4枚タップ1件を追加した。Node自動テスト **363件全件成功**。最終CIのChrome/WebKitは実際のActions結果を参照。

## 原作再現の観点から残る作業

- 複数特殊効果を持つ防具／防御用雑貨を同時に選んだときの実際の効果優先順位を、信頼できる原作操作動画、スクリーンショット、または学校での実際の原作対戦で確認する。
- 未実装の「栄光」など災いによる防具枚数制限は、災いシステムのフェーズで追加する。
- 安全な部分だけ段階的にサポートする。複数選べるという一般則を拡張し、未照合の効果発動まで独断で追加しない。

## 追補：防御の「同時使用できない」制約を先に調べる（2026-10-28）

**利用者からの原作操作指摘:** 奇跡への防御では反射・弾く・数値防御を一度に使うのではなく、対応を選ぶという認識。

追加照合した公開資料：
- https://w.atwiki.jp/piong/pages/21.html の防御面は、奇跡を「止める」「はね返す」対応を比較する戦術解説。**特殊効果の防具と弱い防具を同時選択できないという明文は再照合時に見つからなかった**。前回追補で「明記」としたのは根拠のない誤記だったため撤回する。
- https://w.atwiki.jp/piong/pages/17.html に「止める」「弾く」「はね返す」の独立した効果が明記される。特に止めるは通常防御（守の引き算）とは別の特殊効果。
- https://w.atwiki.jp/piong/pages/16.html に「防具は好きな数タップ」という一般則があるが、上記特殊効果に対する例外を否定しない。
- https://w.atwiki.jp/piong/pages/28.html に公式「修行」1〜8体のCPU戦モードがある。
- https://github.com/BrandenXia/godfield-bot のREADMEは **Playwrightで公式ブラウザの修行モードをヘッドレス操作している**ことを明記。原作への接続テストを行うための技術的先例が存在する。

**確度と保留（2026-10-28再評価）**：止める・弾く・はね返すの各単独効果および防具を複数枚使用できる一般則は資料で確認した。一方、奇跡に対する「弾く＋弱防具」「スカイ＋月光」「月光＋エンゼル」等の**操作上の排他規則は原作で直接確認できておらず未確定**。以前の「同時不可が資料に明記」という評価は撤回する。

**次の検証**：原作の「修行」へアクセスし、原作から見える手札の選択可能状態・同時選択時の挙動・弾く/反射を試す。原作の実プレイ・録画・クライアント状態の確認ができるまでは**「全特殊防具は排他」と推定してロジックを追加しない**。

※本追補は**資料調査のみ**。現在のチャットで公式修行モードの実対戦を実行した証拠ではない。制作ゲームのNode / Chrome / WebKit CIは原作ゲームプレイとは異なる。main、学校Google Sites版は変更していない。


## 再調査・開発版の選択制限の扱い（2026-10-28）

- 原作プレイのBOT研究：[BrandenXia/godfield-bot](https://github.com/BrandenXia/godfield-bot)。`src/godfield_bot/full_game_combat_plan.py` が2026-09収集の公式クライアント/API/教典のデータから、**block / reflect / bounce** を別の効果クラスとして検査。スカイ5種・月光3種・エンゼル4種・スーパーミラーのモデルIDと効果・価格・抽選枠の対応を確認。
- ただし「exclusive special defenses」というBOT側の設計表現は原作クライアントの**複数選択を禁止する直接証拠ではない**。本家修行での画面操作は、今回利用できるコンテナのネットワーク制限により実施できなかった。
- `v2/lab-controller.mjs` に **研究用UIのフェイルクローズ** を追加。奇跡に対して、実装済みの単独対応以外に「止める＋弾く」「スカイ＋月光」「弾く＋普通防具」などをタップした時点で、「この検証版では...」と理由を表示して未確認の複合処理をしない。原作側の禁止を確定した変更ではない。
- 防御奇跡〈乱気流〉→直後の精霊は既知の例外として許可。対武器の通常防御では、スカイ/月光は印字された守備値として他の防具と併用可能。手札4枚以上の通常防御も維持。
- `tests/lab-ui-v2.test.mjs` に新しい回帰ケースを追加し、`tests/v2-webkit-smoke.browser.mjs` にはSafari系エンジンの埋め込み実タップ確認を追加。**原作実機の動作とは区別**して記録する。
