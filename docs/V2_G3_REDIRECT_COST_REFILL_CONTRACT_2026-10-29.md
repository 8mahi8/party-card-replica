# G3→G4｜反射・弾く時の費用／習得／手札補充／次手番の契約（2026-10-29）

## 何を確認したか

前回までに、武器・奇跡の反射先選択と乱数は `v2/redirect-route.mjs` に共通化した。今回の次の重要課題は、**反射が何回起きても攻撃と防御のカード消費、奇跡MP、習得・再使用によるドロー、手番移行が一度だけ正しく発生すること**である。

カードの種類ごとに類似したテストを追加するよりも、出費や補充の境界に関する **G4 golden contract** をデータ駆動の既存エンジン上に作った。

## 原作資料と仮定の分離

- [ゴッドフィールドwiki：ゲームの仕様](https://w.atwiki.jp/piong/pages/16.html) — 使用した神器は使用枚数分補充、初期9枚、手札18枚上限、習得済み奇跡の再使用、攻撃・防御の順序。
- [ゴッドフィールドwiki：防具](https://w.atwiki.jp/piong/pages/17.html) — 跳ね返す／弾く、奇跡専用のスカイ・月光系神器、防御効果。
- [God Fieldガイド＋α：奇跡一覧](https://w.atwiki.jp/gfplusa/pages/19.html) — 奇跡の消費MP、習得、精霊のぬいぐるみによる直前奇跡のMP免除。
- [ゴッドフィールド初心者向けルール説明](https://godfield-beginner.game-info.wiki/) — 攻撃・防御および弾く／跳ね返すの基本動作の独立照合。
- **原作APIや2026年現行版でこの7通りのカード組合せを直接再生したわけではない**。各部品の仕様が根拠を持つことと、複合操作全体が原作で確認されたことは別。今回のテストは**研究版エンジンの整合性・退行防止**が対象。

## 実装とテスト

新規 `tests/redirect-cost-refill-contract-v2.test.mjs` **7ケース**：

1. **武器＋オーラ＋精霊 → スーパーミラーで反射 → 元攻撃者に命中**：MP0消費、手札消費A3枚/B1枚、反射中の補充0、決着時にA3/B1補充。攻撃者HP20、元の状態不変。
2. **武器＋火の玉2枚＋精霊 → スーパーミラーで2回反射 → 最後に普通の防具で受ける**：奇跡MP2（合計4から最後の2のみ免除）、反射中も二重支払なし、最終A5/B2補充、対象HP31。使用済み神器の`instanceId`は最終手札に混入しない。
3. **習得済み氷 → 習得済み乱気流＋精霊 → 元攻撃者が防具で防ぐ**：攻撃者のMP2、守備者の精霊免除MP0、再使用する奇跡によるドロー補充クレジットと物理カード消費を両プレイヤーへ正確に還元。最終HP39、MP8/10、手札2/2。
4. **3人：氷 → スカイヘルムで弾く → 月光のかぶとで跳ね返す → 元の防御者が水攻撃を火属性防具で防ぐ**：A1/B2/C1枚補充、攻撃者MP2のみ、他2人はMP消費0、対象HP39、手番は元攻撃者の次のB。
5. **武器＋オーラ → 防御者が自分へ弾いてしまう**：防御機会を再提示せずHP20、攻撃者MP6と補充2、防御者の弾きカード補充1、未使用防具のインスタンスは維持。
6. **反射後の不正な防御カード選択**：未所持インスタンスでのコマンドはAPI境界で拒否、反射中の保存済みクレジット・revision・状態を変更しない。正しい選び直しで同じ攻撃が決着し、費用と補充は一度だけ。
7. **3人ルームで使ったのはA・Bだけ**：未使用のCは補充イベントが0件で手札と個体IDが不変。元の攻撃者が全員にカードを補充してしまう退行を防止。

### 追加した共通の検証

- 各反射地点で`state.phase==='defense'`、ターンカウント0、保留中の攻撃と`spentByPlayer`継続、補充・次ターンイベントなし。
- 最終的に`state.pending===null`、1回だけ次ターン移行、該当プレイヤーへの補充クレジット数、全手札の個体ID。
- 元のstate JSONが変化しない（誤操作・再試行でも原子的）。
- *注：このテストは固定`d001`補充の研究用fixtureであり、原作の500枠抽選を再現するものではない*。

### CI

- Node／Chromium／WebKitの3ワークフローを最終開発コミットで検査する。実行ログの run IDs・成功件数・最終SHAを Draft PR #1 に記録。
- V2エンジンのゲームコード・UIソースを変更せず、**テストと資料のみ**追加。単体HTMLの再生成は不要。
- GitHub `main`、学校 Google Sites 公開版には一切変更しない。

## 次の段階

G3の共通効果エンジンはMP・ドロー・補充・遷移・反射の退行を検出できるようになった。引き続き**原作実操作・攻撃ダメージの直接証拠**を収集してG4の本物の golden 原作ケースを増やす。

「パンチ→力の粉→オーラ→精霊」は原作API研究で選択可能と判明しているが、**攻撃力の最終数値はまだ直接確認できず**推測実装しない。オンラインG6と全カードG7も未完了。
