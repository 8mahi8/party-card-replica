## G2：統一した順序付きコマンド

`v2/staging-room.mjs` に `playSequence` を追加。従来の `playCards`（手札のみ）と `castLearned`（習得済みの単体奇跡）は保持。

```json
{
  "commandId": "move-001",
  "actorId": "A",
  "expectedRevision": 8,
  "type": "playSequence",
  "targetId": "B",
  "orderedPlays": [
    {"instanceId": "ci-123"},
    {"learnedDefinitionId": "m004"},
    {"instanceId": "ci-124"}
  ]
}
```

- **手札カード**は個別の `instanceId`、**習得済み奇跡**は `learnedDefinitionId`。インデックスで指定しない。
- 両方を**同じ順序配列**に入れることで「武器→習得済みオーラ→追加武器」や「武器→習得済み火の玉」の宣言が可能。
- コマンドの送信者と `authorizedSeatId` が一致しない、所持していないカード、未習得奇跡、二重カード選択、同じ習得済み奇跡の繰り返し、未知フィールド、以前のrevision、同一commandIdの改ざんは拒否。
- `state.pending.attackSequence` と `attackInstanceIds` を両方保持し、反射中に順序が消えないようにする。`viewStagingRoom` が相手に秘密のカード順列を送信することはない。
- 現時点で `playSequence` は**武器から開始する攻撃のみ**。単独の習得済み攻撃奇跡は既存の `castLearned` に任せる。

## G3：共通攻撃コンパイラの変更

`v2/ordered-attack.mjs` は上記の順序列を読み込み、手札カードと習得済み奇跡を同じ型付き効果タグへ変換する。

- 手札由来のカードは実際に消費する。習得済み奇跡は**手札カードを消費せず、使用1回分の追加ドロー**を `grantDraw` 命令として積む。
- MPは複数の奇跡から合計し、精霊が選択列の**直前の奇跡**に隣接する場合は、その1回分だけMP0。
- 習得済み `m004`（オーラ）の倍化は、途中に置かれていても全武器攻撃値の合算後に行う。
- 習得済み `m005`（火の玉）と `m006`（流星）は武器への追加攻撃として加算。
- 同種2枚の火の玉を手札から選ぶ既存確認ケースは残すが、習得済み火の玉を2回同一ターンに混ぜるケースは原作動作未確認のため**拒否**。
- 未確認のオーラ＋火の玉同時効果、自分への補助奇跡攻撃なども拒否。既存の個別カード名による戦闘分岐を再導入しない。

## G3：反射中の清算を共通処理へ統合

以前は、反射の対象変更中だけ使用カードを手動で除去していたため、攻撃補助奇跡のMP・習得・手札増加処理を引き継げず、補助奇跡付き反射を拒否していた。

今回は `v2/effect-runner.mjs` に **`interruptionOnly`** を追加した。これは解決待ちの攻撃を保持したまま、`spend`・`mp`・`learn`・`grantDraw` の命令だけを実行するモード。

```text
手札/習得済みを混ぜた攻撃宣言
→ 最初の反射・弾き：攻撃側の支払い/習得/補充クレジットを1回だけ記録
→ 反射カードの消費（複数人の反射でも各自1回）
→ 現在の攻撃元と対象を変更し、状態のJSONを保存可能
→ 最終的な防御・着弾：攻撃力を再計算せず解決
→ 生存者へクレジットをもとに補充、次の手番へ
```

- `v2/redirect-resolution.mjs` の費用処理は、手動の消費ロジックでなく**共通キュー**へ委譲。
- 反射が2回以上続いても `attackContext` がある限り、攻撃者のMPを再度払わない。
- 自分へ弾き戻った場合は追加防御なしで解決。〈壁〉で止める場合も、使用した補助奇跡の費用が清算される。
- 費用を支払う処理でも入力状態を直接変更せず、検証後の**新しい状態**を返す。通信層における原子的保存・認証は別工程。
