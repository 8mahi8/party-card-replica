# V2 G3/G7｜HP吸収共通処理：実装・原作照合・安全境界（2026-10-30）

## 結論

研究用V2の通常武器処理に**データ駆動のHP吸収**を実装。ゴーストソード（攻7・¥10・参考1/500）とリアルゴーストソード（攻12・¥15・参考1/500）を登録し、通常武器／防御／反射・弾き／自己攻撃／オーバーキル／HP上限99を同じ共通処理で解決する。カード名で分岐していない。

**この2種類の追加だけで本家が完成したわけではない。** 部分研究台帳 **118種類・307/500参考枠**。原作の完全カード抽選、状態異常、全カード、オンラインG6、学校iPad Safariは未完成／未検証。

## コード差分

1. `src/verified-basic-cards.mjs`: `w048`、`w049`。共有`main()` factory に`hpAbsorb:true`を渡す。
2. `v2/legacy-adapter.mjs`／`v2/foundation.mjs`: ホワイトリスト化した`{when:'afterHit',type:'absorbHp',params:{amount:'damage'}}`へ変換、タイミング／スキーマ異常を拒否。
3. `v2/ordered-attack.mjs`: 合法な攻撃の`absorbsHp`をimmutableな攻撃contextに保持。複数の吸収本体の同時使用は仕様未確認のため拒否。他の合法な攻撃値加算との併用は通常のコンパイラを共有。
4. `v2/basic-resolution.mjs`: 最終命中でのみ`lifeSteal:true`を共有効果キューの`hit`へ付ける。防御で軽減された正味ダメージを使用。HP0＋他人の太陽のお守りは優先順未確認のため拒否。
5. `v2/effect-runner.mjs`: 本当の吸収カードが攻撃contextにあることを検証し、`damage`イベント後**同一`hit`で1回だけ**現在の`pending.sourceId`にHPを加算、上限99。自己攻撃ではHP0を一時的に通過しても自己吸収による復帰を先に行い、太陽のお守りを消費しない。他人へ致死攻撃時はその対象の復活有無を確認する。
6. `v2/hit-outcome-boundary.mjs`: 前回のダメージ差分境界を既存の新機能で再利用。
7. `tests/lifesteal-weapon-v2.test.mjs`: **14ケース**。基礎吸収、防御軽減、完全防御、致死オーバーキル、自己吸収2種、HP99上限、反射先の持ち主変更、自己への弾き、太陽のお守り未確認組合せの拒否、偽命中フラグ拒否、無効スキーマ、二重吸収登録拒否など。
8. 旧単体HTMLとV2研究用30モジュール単体HTMLを再生成。テスト用抽選`d001`は変更なし。

## 特に重要な優先順位

```text
認証済み攻撃選択 → コンパイル・費用チェック → 相手の防御
   → (反射/弾きなら未確定の攻撃contextを保持し対象を変更)
   → 最終命中の防具・属性の計算
   → HP減少 → （吸収なら現在の攻撃元へ正味攻撃ダメージ分の吸収）
   → 自己吸収でHP>0になった場合は復活護符を発動しない
   → 他人のHP0は通常の受動復活検査 → 1回だけ補充 → 次手番
```

**HP1 → 自分へ攻12 → 一旦0 → HP12** であり、`max(0,1-12)+12=12`。`hpLost=1`を回復量に流用してHP1で止める誤りを禁止。

反射は現在の`sourceId`を変えるため、元の攻撃者が吸収するのではなく、実際の最終の「攻撃元」が吸収する。原作資料の強い例がある自己弾きと、共通反射経路を検証。

## 未対応・保留

- **他人への致死HP吸収＋太陽のお守り**は、吸収・自動復活・補充の原作の正確な順序が取れていないのでfail-closed。自己吸収は2023/2026資料に基づき護符非発動。
- **吸収奇跡＜吸収＞**は奇跡の`afterHit`共通化と防御・反射の総合検証後に追加。
- 特殊武器との同時使用、2回攻撃＋吸収、災い＋吸収の順序、攻撃力を大きくする未確認カードとの併用、HP以外の受動反撃・守護神は未実装。
- ブラウザテストはLinux Chromium／Playwright WebKitの短いiframe操作。iOS SafariやGoogle Sitesの実ページ、2台オンライン検証ではない。
- 原作画像・ブランドの配布素材としての転載はしない。
