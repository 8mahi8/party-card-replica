# V2 G5｜固定高さの埋め込み枠を使った操作検証（2026-10-27）

## 目的

学校iPad Safariで遊ぶためのGoogle Sites「コード埋め込み」を想定し、**高さが固定された小さなiframeの中で**V2のホットシート試遊画面が操作できるか、実際のChromeを動かして確かめた。

**重要：これはGoogle SitesやiOS Safariを実行したものではない。** `v2/demo/embed-harness.html` は開発用のローカル枠であり、Google Sites固有のiframe制限・権限・ページ配置を完全に再現しない。

参考：
- [Google Sites公式ヘルプ（HTML/CSS/JSの直接埋め込み）](https://support.google.com/sites/answer/90569?hl=ja)
- [埋め込み枠の高さとモバイルの切れに関するSitesフォーラム](https://support.google.com/sites/thread/469870763/responsive-height-scaling-and-iframe-embed-clipping-issues-on-mobile-viewports-in-google-sites?hl=en-AU)
- [Playwright公式のWebKit説明](https://playwright.dev/docs/browsers)（Linux WebKitでも本物のiOS Safariとは異なる。今回WebKitテストはまだ未導入。）

## スクリーンショットで見つけた実際の問題

最初の26項目合格時（Chrome run **40520486664**）に画面を目視すると、横幅は正常でも、**高さ460px／430pxの埋め込み枠では交代画面の「自分の手札を見る」ボタンが画面外に隠れていた**。既存のブラウザチェックはスクロールすればボタンを押せるので気づけなかった。

そこで次の変更を行った：

1. `v2/lab-ui.mjs`：交代画面では大きなHP情報と長い説明を一時的に省略。カードを隠す安全性はそのまま維持し、次の人の名前と手札を見るボタンを優先。
2. `v2/demo/template.html`：`compact-pass` の高さ・余白・装飾を小さなiframeでも収まるよう調整。
3. 手番が次の人へ変わったとき、**iframe自身のスクロール位置だけを先頭へ戻す**。ホスト側ページのスクロールは操作しない。カードを選んでいる最中もスクロールを勝手に戻さない。
4. 次の人へ渡す説明を「相手の防御を待っています」から**「防御するプレイヤーに端末を渡してください」**へ訂正。

### 実ブラウザテスト

`tests/v2-browser-smoke.browser.mjs` は既存の直接HTML操作に加えて、ローカルHTTPサーバーで `v2/demo/embed-harness.html` を配信し、以下を実際のChromeで検証する：

- 1024×460の枠／390×430の枠に単体HTMLを読み込み
- 相手の手札が渡す前に見えない
- iframeの横はみ出しがない
- 手札選択→枠内を最下部へスクロール→固定された攻撃確定ボタンを押す
- 端末交代画面の表示と**iframeのスクロール位置の復帰**
- 長い説明を短縮した交代画面の**「自分の手札を見る」ボタンがスクロールなしに枠内に表示**
- 狭い枠でも確定ボタンが可視で高さ44px以上

### 検証記録

- 変更前の固定高さiframe検証：**実ブラウザ26/26項目成功**（run 40520486664）だが、画像を目視すると交代ボタンが画面外にある問題を発見。
- 交代画面を修正後：**実ブラウザ28/28項目成功**（run 40521339510）、Node.jsの**302/302テスト成功**（run 40521339484）。
- その後、交代画面の文言も訂正（最新HTMLを再生成）。文言を確認するNode回帰テストに反映。
- `v2-browser-evidence` アーティファクトに `embed-ipad-handoff.png` と `embed-mobile-handoff.png` を含めている。**画像を実際に目視し、どちらの枠でも交代ボタンが画面内にあることを確認**。

## まだ確認していないこと

- 実際の学校iPad Safariでの画面内スクロールとキーボード・タッチの細部
- Google Sitesの埋め込み枠内で約100KBの単体HTMLが受理されるか、iframeのsandbox/CSPや親ページの高さ・スクロール制約
- 2台のiPad間のオンライン接続（現在はオフライン1台交代制）
- 公式原作との全カード・出現率・特殊効果の完全一致

実物を学校で試すまで「Safari／Google Sites対応確認済み」にはしない。**開発ブランチのDraft PRのみ更新し、mainと学校のGoogle Sites版は触らない。**
