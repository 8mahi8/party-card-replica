# V2 G3｜防御側の順序選択・〈壁〉＋精霊のMP無料（2026-10-27）

## この工程の目的

原作の防御奇跡〈壁〉と補助雑貨〈精霊のぬいぐるみ〉を組み合わせ、**精霊は直前に選ばれた奇跡だけをMP無料にする**という選択順を、G2のルーム操作とG3の共通効果キューの両方で再現する。

前段階のV2では攻撃側に `playSequence` があったが、防御側は通常 `defend(orderedInstanceIds,learnedDefinitionId)` のみで、**習得済み〈壁〉→精霊**の順を表現できなかった。

### 原作の根拠（公開資料）

- [God Fieldガイド＋α・奇跡](https://w.atwiki.jp/gfplusa/pages/19.html)：〈壁〉MP6、奇跡以外の無属性武器攻撃を停止。精霊系神器は**直前に選択された奇跡**へ効果がかかる。
- [ゴッドフィールドwiki・新版情報](https://w.atwiki.jp/gfkuryk/pages/15.html)：精霊のぬいぐるみは**攻守両方で使用可能**と記載。ただし古い変更履歴を含むため現在のゲーム版と照合する必要あり。
- [God Field wiki・神器一覧（その他）](https://w.atwiki.jp/piong/pages/19.html)：精霊のぬいぐるみはMPを消費せず奇跡を使用できる。
- [ゴッドフィールドwiki・ゲームの仕様](https://w.atwiki.jp/piong/pages/16.html)：習得済み奇跡の反復使用と虹のカーテンの属性解除。

**あくまで第三者資料との照合**。現行公式サーバー／iPadでの同条件プレイは未実施であり、細かい例外ルールの版差は残る。

## 今回の変更箇所

- `v2/staging-room.mjs`：`defendSequence` を追加。型付きの `orderedPlays: [{instanceId},{learnedDefinitionId},{instanceId}]` で、**手札と習得済み奇跡の順序を一つの配列として保存**する。既存 `defend` は互換維持。
  - 手札に存在しないID、未習得の奇跡、攻撃用の奇跡、同じ手札カード2回、習得済み防御奇跡複数、先頭に選んだ精霊、虹のカーテンが先頭でない入力を拒否。
  - 再送はcommandId＋payloadを指紋化。revisionと認証済み席IDの確認を維持。対戦相手には防御の秘密選択順を送らない。
- `v2/wall-resolution.mjs`：`defense.sequence` の順序に沿って、防御雑貨（虹のカーテン）・奇跡〈壁〉・精霊を**1回ずつ判定**する。精霊が壁の直後にある場合のみMP6→0、それ以外はエラー。停止・学習・手札消費・追加ドロー・ターン進行は既存共通 `effect-runner.mjs` を使用。
- `v2/lab-controller.mjs`：防御時に習得済み奇跡を選んだ後、精霊をタップで追加できるように変更。習得済み奇跡がある場合は新しい `defendSequence` を発行。表示だけの順序とエンジン側の順序がずれない。
- `v2/demo/standalone.html`：上記の最新版をビルドして単体HTMLへ反映。固定テスト用山札のままで、正式版ではない。

### 正常とする選択順

| 防御カードの選択順 | MP | 対象 |
|---|---:|---|
| 壁（手札） | 6 | 無属性武器 |
| 壁（手札）→精霊 | 0 | 無属性武器 |
| 習得済み壁 | 6 | 無属性武器 |
| 習得済み壁→精霊 | 0 | 無属性武器 |
| 虹のカーテン→壁→精霊 | 0 | 属性武器から無属性化 |
| 虹のカーテン→習得済み壁→精霊 | 0 | 属性武器から無属性化 |

精霊が直前の壁と隣接しない場合、壁なし、壁と関係ないカード混在、精霊2枚連続、虹のカーテンが先頭ではない場合は拒否。

### 具体的な通信前の開発用コマンド例

```json
{
  "commandId": "defend-123",
  "expectedRevision": 12,
  "actorId": "B",
  "type": "defendSequence",
  "orderedPlays": [
    {"learnedDefinitionId": "m001"},
    {"instanceId": "ci-987"}
  ]
}
```

※ `actorId` はクライアントが任意に詐称できる。オンラインにするときは信頼できる接続の本人席との照合と保存の原子的更新が必要。
