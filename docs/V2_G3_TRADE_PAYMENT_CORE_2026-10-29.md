# V2 G3｜「売る」の支払い計算を先に独立化（2026-10-29）

## 原作資料と確証の範囲

- [アニヲタWiki ゴッドフィールド・取引](https://w.atwiki.jp/aniwotawiki/pages/47010.html)：押し売りは対象の所持金から支払い、それが不足したらMP、さらに足りなければHPを代用。例として対象の **HP15 / MP10 / 所持金5** の状態で **¥25** の金のこん棒を買わされると **HP5 / MP0 / 所持金0** になる。
- [ゴッドフィールドwiki：取引一覧](https://w.atwiki.jp/piong/pages/19.html)：**売る／買う／両替の各取得率は4%（500枠中20）・価格は¥5**。売るは自分の神器を1つ相手に押し付け、足りない分は¥→MP→HPの順で差し引く。
- [God Fieldガイド＋α](https://w.atwiki.jp/gfplusa/pages/18.html) にも同じ順序。
- [1000試合の実践報告](https://note.com/md_stardustman/n/nfc5dfb559f95)：売ると自分の手札は1枚減る。買うと手札が1枚増える。手札上限18枚。

## 今回追加した純粋計算（本体取引はまだ未実装）

- `v2/trade-payment.mjs`：`planForcedSalePayment({price,buyer})` を新設。
- 入力はカード価格・買わされる側の公開HP/MP/所持金。元状態を変更せず `debit:{money,mp,hp}`、`buyerAfter`、`paid`、`unpaid`、`buyerEliminated`、`settlement`、`sellerCredit` を返す。
- お金→MP→HPの優先順位は原作資料に基づく。負の残高・小数や危険な整数を禁止。返すプランはObject.freeze。
- 全リソースで代金に届かずHP0になる場合、**売り手が代金を全額受け取るのか、回収できた分だけなのか、原作の直接データがない**。ここでは `settlement:'lethal-unverified'` と `sellerCredit:null` を返し、**本番の取引画面へ適用しない**。そのため、原作の未確認動作を勝手にゲームに混ぜない。

## テスト

`tests/trade-payment-v2.test.mjs` に7テスト：原作の数値例、¥→MP→HPの順序、価格0の奇跡売却、残高ちょうどでHP0、代金未払いでHP0のときの未確定マーク、価格0〜100の残高保存則、不正な金額・ステータスの拒否。

`v2/trade-payment.mjs` はまだ `v2/demo/build.mjs` の起動モジュールに入れない。これは**戦闘から呼ばれていない独立研究用ライブラリ**。後で実戦の売る処理を追加するときだけ、利用側のコマンドと合意済み仕様を作成して導入する。
