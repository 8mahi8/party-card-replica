# V2 G3｜奇跡の防御方法を選び直すUI（2026-10-28）

## 根拠・位置づけ

利用者は本家ゴッドフィールドのプレイ経験に基づき「奇跡への特殊防御は、警告ではなく、後からタップした防御へ**入れ替わる**」と報告した。これは原作を知っているプレイヤーからの具体的な操作フィードバックで、**開発担当AIが本家「修行」を今回実際に操作したという意味ではない**。

前段階では、奇跡に対する複数の反射・弾く・止めるを選ぶとエラーメッセージを出していた。その挙動は本家と異なるため、開発用UIの選択仕様を改善した。

## 実装した挙動

- 奇跡が来ている防御フェーズで、新たに〈弾く〉〈はね返す〉〈止める〉の特殊対応をタップすると、それまでの防御選択は解除され、**最後にタップしたカードのみ**が選択される。
- 特殊対応を選んでいる状態から普通の防具へ変更すると、特殊対応を解除して**通常防具での防御**へ切り替わる。
- 普通の防具を複数選ぶ動作は維持。そこから特殊防御へ変更すると普通の防具の選択を解除する。
- 習得済み奇跡・手札の防御奇跡についても、カードの効果タグ（`stopAttack` / `redirectAttack`）に基づき判断。カードの日本語名で分岐しない。
- 防御奇跡（例：乱気流）を選んだ直後の精霊は**MP無料の補助**として選択を維持。そこから別の特殊対応をタップすると精霊も含めて選択が入れ替わる。
- 防具反射を選んだ後に精霊だけをタップしても、防具の選択は変えない。これは未対応な「精霊単独の防御選択」を作らないための実装上の安全策であり、原作のその細部まで検証済みとの主張ではない。
- **再タップで選択解除**も従来どおり。特別な警告を出さず、選択済みカードの強調が変化する。

## 安全性と未確認事項

- この実装は`v2/lab-controller.mjs`の**試遊UI操作**の正規化。権限チェック・原子的な解決・不正な複合防御を拒否するサーバー側相当の`v2/staging-room.mjs`・`v2/miracle-resolution.mjs`の検証は緩めていない。
- 自動選択切替は**奇跡攻撃に対する防御**限定。通常の武器攻撃は複数枚防具の数値合算を保持。
- 本家での特殊防具同士の全組み合わせ、精霊など補助雑貨の細部は後続の本家修行観測で確認する。
- 自動テストは`tests/lab-ui-v2.test.mjs`、Safari系WebKitの埋込タップ試験は`tests/v2-webkit-smoke.browser.mjs`を更新。WebKitで「スカイ→月光→スカイ→月光」のスイッチ・警告なし・実際に反射してP1に戻るまで確認。
- テスト実行環境はPlaywright WebKit（Linux）であって**本物の学校iPad Safariでも、本家ゲームの原作クライアントでもない**。
- 開発はDraft PR #1、ブランチ`refactor/v2-foundation-review-20261027`のみ。main・Google Sites版は変更しない。
